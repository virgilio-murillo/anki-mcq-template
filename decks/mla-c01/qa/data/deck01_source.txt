A financial institution is working on a machine learning model for predicting loan approval decisions. The institution prioritizes explaining lending decisions to stakeholders in human terms for transparency and fairness.

Which of the following machine learning model statements is true, and which does the institution need to choose to meet the requirement?

A simple model should be chosen because explainability is crucial in loan approval decisions.
A simple model should be chosen because accuracy is more important than explainability in loan approval decisions.
A complex model should be chosen because explainability is crucial in loan approval decisions.
A complex model should be chosen because accuracy is more important than explainability in loan approval decisions.
Incorrect
Machine learning (ML) is the process of training computers, using math and statistical processes, to find and recognize patterns in data. After patterns are found, ML generates and updates training models to make increasingly accurate predictions and inferences about future outcomes based on historical and new data. For example, ML could help determine the likelihood of a customer purchasing a particular product based on previous purchases by the user or the product’s past sales history.

What are simple and complex machine learning models?

Simple and complex ML models differ when balancing a model’s accuracy (number of correctly predicted data points) and a model’s explainability (how much of the ML system can be explained in “human terms”). The output of a simple ML model may be explainable and produce faster results, but the results may be inaccurate. The output of a complex ML model may be accurate, but the results may be difficult to communicate.

simple-vs-complex-ml-model

In the context of developing a machine learning model for predicting loan approvals, a financial institution prioritizing transparency and fairness over maximizing accuracy should opt for a simple model that is easily explainable. Transparency in lending decisions is crucial to ensure fairness and mitigate biases. Simple models such as decision trees or logistic regression provide clear visibility into the factors influencing loan approval, making it easier to explain why a decision was made. While accuracy is important in predicting loan approval decisions, the ability to explain why a particular decision was made is equally critical. Additionally, complex models might offer marginally better predictive accuracy, they often lack transparency, making it difficult to justify decisions to stakeholders and regulators.

Hence, the correct answer is: A simple model should be chosen because explainability is crucial in loan approval decisions.

The option that says: A complex model should be chosen because accuracy is more important than explainability in loan approval decisions is incorrect because it prioritizes accuracy over explainability, which is the requirement in this scenario. Furthermore, while accuracy is important in predicting loan approvals, it cannot be prioritized over explainability in this context. Financial institutions must ensure their decisions are transparent and fair, which is difficult with complex models like deep neural networks or ensemble methods that lack interpretability. Regulatory bodies often require institutions to provide clear reasons for loan approval or denial, making explainability crucial.

The option that says: A simple model should be chosen because accuracy is more important than explainability in loan approval decisions is incorrect. This option correctly identifies the use of a simple model but incorrectly states the reason. The emphasis here should be on explainability, not just accuracy. While simple models can sometimes be less accurate than complex ones, their interpretability makes them more suitable for loan approval decisions where transparency is essential.

The option that says: A complex model should be chosen because explainability is crucial in loan approval decisions is incorrect. While it correctly states that explainability is crucial, it incorrectly suggests using a complex model. Complex models are typically less interpretable, making it difficult to explain the decision-making process. For ensuring fairness and transparency, simple models that are inherently more interpretable are preferred.

The option that says: Production data is always consistent with training data, making retraining unnecessary is incorrect because production data is rarely consistent with training data over extended periods. This inconsistency requires regular monitoring and retraining of the models to ensure they continue to perform well.

The option that says: Once a machine learning model is deployed, it can remain effective indefinitely without updates is incorrect because machine learning models must be regularly updated to account for changes in data patterns and maintain their performance. What is the most effective strategy to meet these requirements?

Organize the data into separate folders based on file type. Use DataBrew to process each folder separately and save the output in Apache Parquet format.
Process the data in the current S3 folder using DataBrew and store the output in Apache Parquet format.
Process the data in the current S3 folder using DataBrew and store the output in JSON format.

Incorrect
AWS Glue DataBrew is a visual data preparation tool enabling users to clean and normalize data without writing code. Using DataBrew helps reduce the time it takes to prepare data for analytics and machine learning (ML) by up to 80 percent, compared to custom-developed data preparation. You can choose from over 250 ready-made transformations to automate data preparation tasks, such as filtering anomalies, converting data to standard formats, and correcting invalid values.

DataBrew Overview Diagram

Using the DataBrew console, you can browse Amazon S3 buckets and directories to select a file for your dataset. Datasets are not restricted to a single file. DataBrew is capable of processing all files within an S3 folder, provided that two conditions are met:

1. All files share the same data format.

2. All files use the same file extension.

DataBrew supports using the Apache Parquet format. This column-based data format is preferred due to its performance orientation, especially with large datasets.

Hence, the correct answer is: Organize the data into separate folders based on file type. Use DataBrew to process each folder separately and save the output in Apache Parquet format.

The option that says: Process the data in the current S3 folder using DataBrew and store the output in Apache Parquet format is incorrect. The question specifies that the S3 folder contains multiple file types, all stored in the same folder. DataBrew can only process all files in a folder if they share the same format and file extension. Since this folder contains heterogeneous file types, it violates both requirements.

The option that says: Upload all files to a single S3 folder. Use Glue to convert them into JSON format before processing with DataBrew is incorrect. This option suggests using AWS Glue first to convert the files to JSON before processing them with DataBrew, which is backwards. DataBrew is typically used before Glue jobs to perform cleaning, normalization, and transformation. Also, storing and exporting output in JSON is technically possible but not optimal for AWS Glue, which performs best with columnar formats like Parquet. This format choice would result in slower performance and increased cost in Glue-based ETL jobs.

The option that says: Process the data in the current S3 folder using DataBrew and store the output in JSON format is incorrect. This option simply combines the inability of DataBrew to process heterogeneous file types and the slow performance of the JSON format, making this option completely unworkable.

Amazon Data Firehose

Incorrect
Amazon Kinesis Data Streams is a scalable and durable real-time data streaming service offered by AWS. It allows you to continuously capture and store terabytes of data per hour from hundreds of thousands of sources, such as website clickstreams, database event streams, financial transactions, social media feeds, and IoT sensor data.

Kinesis Data Streams can automatically scale to handle varying data volumes and provide features like data retention, data replication, and automatic load balancing. It is designed to handle real-time data ingestion from various sources and can be integrated with other AWS services like Amazon Managed Service for Apache Flink Studio, AWS Lambda, and Amazon SageMaker for real-time data processing and analysis.

Apache Flink is an open-source distributed processing engine for stateful computations over data streams. It provides a high-performance runtime and a powerful stream processing API that supports stateful computations, event-time processing, and accurate fault-tolerance guarantees.

Amazon Managed Service for Apache Flink is a fully managed service that enables you to run Apache Flink applications on AWS without having to manage the underlying infrastructure. It automatically provisions and manages the resources required to run Apache Flink clusters, including EC2 instances, Apache Flink runtime, and Apache ZooKeeper.

With Amazon Managed Service for Apache Flink, you can consume data from various sources, including Amazon Kinesis Data Streams, and perform real-time data transformations, filtering, and enrichment. It supports stateful stream processing, allowing you to maintain and update the state as data flows through the application. This service integrates with other AWS services like Amazon SageMaker, Amazon S3, and Amazon Data Firehose, enabling you to build end-to-end real-time data processing pipelines.

Amazon Kinesis Data Streams

By using Kinesis Data Streams and Amazon Managed Service for Apache Flink together, the machine learning engineer can ingest the real-time transaction data from the online payment platform, apply any necessary transformations or preprocessing, and then deliver the processed data to Amazon SageMaker for real-time inference using the pre-trained machine learning model to detect fraudulent transactions.

Hence, the correct answers are:

– Amazon Kinesis Data Streams

– Amazon Managed Service for Apache Flink

Amazon Data Firehose is incorrect. While Kinesis Data Firehose can ingest and deliver data to Amazon S3 or other destinations, it is primarily designed for batch processing and not real-time inference.

AWS Glue is incorrect because AWS Glue is a fully managed extract, transform, and load (ETL) service, primarily used for batch data processing and not real-time data ingestion and processing.

Amazon Managed Streaming for Apache Kafka (Amazon MSK) is incorrect. While this service could technically handle streaming data, it’s mainly used for data transfer between different applications and systems rather than real-time processing and inference.
