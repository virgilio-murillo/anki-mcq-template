An e-commerce company wants to implement a machine learning system to detect fraudulent online transactions. An ML engineer has deployed a machine learning model to identify and minimize these fraudulent activities. However, only a small percentage (around 3%) of the transactions in the dataset are found fraudulent. The company wants to fine-tune the model’s ability to detect fraud while minimizing false positives to ensure genuine transactions are not impeded.

Which metrics should the ML engineer use to optimize the performance of its fraud detection system? (Select TWO.)

Cut-off
RMSE (Root Mean Square Error)
True Positive Rate
False Positive Rate
F1 Score
Incorrect
RMSE (Root Mean Square Error) is a metric used to measure the differences between predicted values and actual values in a regression problem. It calculates the square root of the average squared differences between the predicted and actual values. A lower Root Mean Square Error value indicates better model performance.

True Positive Rate (Recall or Sensitivity), also known as Recall or Sensitivity, is a metric used in classification problems. It assesses the percentage of true positive instances correctly identified by the model. A higher True Positive Rate indicates that the model is better at detecting positive instances.

False Positive Rate is another metric used in classification problems. It measures the proportion of actual negative instances that are incorrectly classified as positive by the model. A lower False Positive Rate is desirable, as it means the model is less likely to misclassify negative instances as positive.

F1 Score is a metric that merges recall and precision into a single score. It is the harmonic mean of recall and precision. Precision measures the fraction of correctly predicted positive outcomes, while recall is the same as the True Positive Rate. The F1 Score provides a balanced measure of a model’s performance by considering both precision and recall.

Cut-off (or threshold) is a value used to convert the model’s predicted probabilities or scores into binary class predictions. Specifically, the cut-off is a threshold value that separates the two classes. Any predicted probability or score above the cut-off value is classified as one class (e.g., positive or fraudulent), while any value below the cut-off is classified as the other class (e.g., negative or genuine).



The problem statement mentions that the company wants to fine-tune the fraud detection model to identify fraudulent transactions while minimizing false positives (genuine transactions incorrectly flagged as fraudulent). By optimizing (minimizing) the FPR, the ML engineer can ensure that the fraud detection system does not unnecessarily flag too many genuine transactions as fraudulent.Remember that FPR directly measures the proportion of genuine (non-fraudulent) transactions that are incorrectly classified as fraudulent by the model. A low FPR indicates that the model is minimizing the number of false positives, which aligns with the company’s requirement. Next is optimizing the F1 Score which helps strike a balance between Precision (minimizing false positives) and Recall (detecting true fraudulent cases). By maximizing the F1 Score, the ML engineer can optimize the model to have both a reasonably high Precision (low false positives) and a high Recall (high true positive rate for fraudulent transactions).

Hence, the correct answers are:

– False Positive Rate

– F1 Score

The option that says: RMSE (Root Mean Square Error) is incorrect because it is a metric primarily used for regression problems, where the goal is to predict a continuous value. In the case of fraud detection, which is a classification problem, RMSE is not an appropriate metric.

The option that says: True Positive Rate is incorrect. The True Positive Rate (TPR) measures how well the model identifies actual fraudulent transactions but does not address the need to minimize false positives. A high TPR indicates that the model detects many fraudulent cases accurately; however, it can also result in a high False Positive Rate (FPR), meaning that genuine transactions might be wrongly flagged as fraudulent. Since the company’s goal is to minimize false positives to avoid disrupting legitimate transactions, focusing on metrics like FPR and F1 Score is more appropriate. These metrics directly address the issue of false positives and ensure that the model effectively balances detecting fraud while minimizing incorrect flags on genuine transactions.

The option that says: Cut-off is incorrect. The cut-off (or threshold) is not a performance metric but only a decision boundary used to classify transactions as fraudulent or not. Adjusting the cut-off is part of the process to optimize performance metrics like precision, recall, and F1 Score, but it is not a metric itself.

A machine learning engineer working in a weather forecasting agency was tasked with selecting appropriate metrics to assess the quality of a time-series forecasting model. The agency uses the model, deployed on Amazon SageMaker AI, to predict future temperatures and humidity levels.

Which metrics are most suitable for evaluating this model? (Select TWO.)

Root mean square error (RMSE)
Log loss
Area Under the Curve (AUC)
F1 Score
Average weighted quantile loss (Average wQL)
Incorrect
Time-series forecasting is a data science technique that uses machine learning and other computer technologies to study past observations and predict future time-series data values. Here are some examples of time-series forecasting:

Astronomical data consists of repetitive movements of the planets over centuries. You can use this data to accurately predict astronomical events like eclipses and comets.

Weather forecasting uses humidity and temperature patterns to predict weather changes.

Product demand forecasting uses historical sales data to predict how many units will be sold in future periods, such as the coming weeks or months.

Product demand and forecasts

The time-series forecasting model in our question predicts future temperatures and humidity levels, both continuous variables. As this is a regression task, the model is evaluated using regression metrics.

Root mean square error (RMSE) is a standard metric for evaluating regression models. RMSE quantifies how far off the model’s predictions are from actual values by penalizing larger errors more heavily. RMSE is calculated by taking the square root of the mean of the squared differences between the actual values and the predicted values

Average Weighted Quantile Loss (Average wQL) is designed for probabilistic forecasting, where one predicts a range (distribution) of possible future values rather than a single point. It’s beneficial in time-series models like those used in weather forecasting, where uncertainty and quantiles matter (e.g., what’s the 90th percentile expected humidity?).

Thus, the correct answers are:

– Root mean square error (RMSE)

– Average weighted quantile loss (Average wQL)

Area Under the Curve (AUC) is incorrect because it is designed only for binary classification, not regression. AUC evaluates how well a model distinguishes between two classes (e.g., positive vs. negative) by plotting the True Positive Rate (Recall) vs. False Positive Rate at various threshold settings. It gives a sense of ranking performance, not exact value accuracy. An AUC score close to 1 suggests the machine learning model performs highly, while a score near 0.5 implies the model’s predictions are roughly equivalent to random guessing.

F1 Score is incorrect because it only applies to classification, not to regression-based time-series forecasting tasks, where we predict continuous values. The F1 score is the harmonic mean of Precision and Recall, both used for binary or multi-class classification tasks.

Log loss is incorrect because it is not typically used for regression tasks. It is primarily a classification metric designed for models that output probabilities for class predictions, rather than continuous numeric values. LogLoss measures the performance of a classification model where predictions are probabilities (between 0 and 1), and the actual labels are categorical (binary or multi-class).

IAM supports two main types of policies:

– Identity-Based Policies: These policies are attached to IAM users, groups, or roles to specify what actions they can perform and on which resources. They define access permissions for individuals or groups.

– Resource-Based Policies: These policies are applied directly to resources, such as S3 buckets or VPC endpoints, to control who or what can access them. They help manage access at the resource level.

IAM Users: When an IAM user is created, it is an AWS identity that has long-term credentials, such as a username, password, and optionally access keys. These credentials are generally used for persistent access, where the user needs to access AWS resources over a long period.

IAM Roles: An IAM role is an AWS identity that has specific permissions and is intended to be assumed by entities (users, applications, services). IAM roles do not have long-term credentials. Instead, they are designed to provide temporary security credentials that expire after a short period, typically ranging from a few minutes to a maximum of 12 hours. When you create an IAM role, you can attach one or more identity-based policies to it. These policies define what actions the role can perform when it is assumed.

A media analytics company is working on a project that analyzes video and image files stored in an Amazon S3 bucket. The company has partnered with an external video processing startup to improve its machine learning (ML) models. The startup uses its own AWS account but requires access to the media analytics company’s S3 bucket to retrieve and process the video files. The startup needs both programmatic and AWS Management Console access to the bucket.

Which solution will meet these requirements most securely?

Enable S3 Block Public Access in the media analytics company's AWS account.
Create a bucket policy in the startup's AWS account, granting access to the S3 bucket.
Use Amazon S3 Access Points to allow the startup access to the S3 bucket.
Create an IAM role in the media analytics company's AWS account, allowing the startup to assume the role and access the S3 bucket.
Incorrect
An IAM role is an AWS identity with specific permissions intended to be assumed by entities (users, applications, services). IAM roles do not have long-term credentials. Instead, they are designed to provide temporary security credentials that expire after a short period, typically ranging from a few minutes to a maximum of 12 hours. When you create an IAM role, you can attach one or more identity-based policies. These policies define what actions the role can perform when it is assumed.

A cross-account IAM role is an IAM role that can be assumed by users or services in another AWS account. This allows for secure access and sharing of resources across AWS accounts.



By creating an IAM role in the media analytics company’s account and granting the necessary permissions to access the S3 bucket, the video processing startup can assume this role and securely access the bucket. This approach follows the principle of least privilege and allows for granular access control.

The process involves:

Creating an IAM role in the media analytics company’s account with the required permissions to access the S3 bucket.
Granting the video processing startup’s AWS account the ability to assume this role using the sts:AssumeRole permission.
The video processing startup can then assume the role and access the S3 bucket using temporary security credentials provided by AWS Security Token Service (STS).
This solution ensures that the video processing startup does not have permanent access to the media analytics company’s AWS resources and can only access the S3 bucket through the assumed role.

Hence, the correct answer is: Create an IAM role in the media analytics company’s AWS account, allowing the startup to assume the role and access the S3 bucket.

The option that says: Create a bucket policy in the startup’s AWS account, granting access to the S3 bucket is incorrect because bucket policies are defined only in the bucket owner’s account, not the account accessing the bucket. Creating a bucket policy in the startup’s account would not grant them access to the media analytics company’s bucket.

The option that says: Enable S3 Block Public Access in the media analytics company’s AWS account is incorrect. While enabling S3 Block Public Access is a recommended security practice, it does not directly address the requirement of granting access to the video processing startup’s AWS account. This option alone would not allow the startup to access the S3 bucket.

The option that says: Use Amazon S3 Access Points to allow the startup access to the S3 bucket is incorrect. S3 Access Points typically provide a network path to access S3 buckets but do not handle access control or authentication. Access Points must be used with other access management mechanisms, such as IAM roles or bucket policies. Additionally, they do not inherently provide a mechanism for granting programmatic and AWS Management Console access across different AWS accounts. IAM roles with cross-account access are still required for this scenario.
