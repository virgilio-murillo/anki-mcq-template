VPC Endpoints · Gateway vs Interface (PrivateLink)

MLA-C01 · tarjeta de estudio · dos formas de llegar a AWS sin salir a internet

Aclaración de nombres: esto es gateway endpoint vs interface endpoint (tipos de VPC endpoint para conectividad privada). No confundir con "inference endpoint", que es el de servir modelos en SageMaker (otro tema).

Escenario de la carta: un training job en us-west-2 debe leer un bucket S3 en us-east-1 (otra región) sin salir a internet, sin duplicar datos y sin cambiar de servicio.

Respuesta: D — interface endpoint (PrivateLink) + conectividad cross-region (peering/TGW).

1) Gateway endpoint — una ruta

Es un objetivo de ruteo: agregas una entrada en la tabla de rutas de tu VPC y el tráfico hacia S3 o DynamoDB va por la red de AWS en lugar de por internet. Es gratis y simple, pero no crea ninguna IP privada ni interfaz de red. Solo funciona para recursos de esa misma VPC y hacia el servicio de la misma región.

2) Interface endpoint (PrivateLink) — una ENI

Crea una interfaz de red (ENI) con IP privada dentro de tu subred. El tráfico entra por esa IP privada y viaja por AWS PrivateLink. Soporta muchos servicios (S3, SageMaker, KMS, ECR...) y, lo clave: puede recibir tráfico desde on-premises o desde otra VPC/región (combinado con VPC peering o Transit Gateway). Tiene un costo por hora + por datos.

3) Por qué existen dos

Existen dos porque resuelven el mismo objetivo (llegar a un servicio AWS sin salir a internet) con mecanismos distintos. El gateway es la opción barata y por defecto para S3/DynamoDB dentro de tu región. El interface es más potente y flexible (más servicios, cross-VPC, cross-region, on-prem, IP privada) a cambio de un costo. No es que uno sea mejor: cada uno cubre casos que el otro no.

4) Cuándo elegir cuál (y esta carta)

Regla: usa gateway por defecto si solo necesitas S3/DynamoDB dentro de la misma VPC y región (gratis). Cambia a interface cuando el gateway no alcanza: otro servicio, acceso desde on-prem u otra VPC, o un bucket en otra región. Esta carta cae justo en el último caso: la VPC está en us-west-2 y el bucket S3 en us-east-1 (otra región). Como el gateway es intra-región, no llega; por eso la respuesta es el interface endpoint (+ peering/TGW).

Regla para el examen: Gateway = ruta en la tabla, gratis, solo S3/DynamoDB, intra-región, intra-VPC.   Interface (PrivateLink) = ENI con IP privada, muchos servicios, admite on-prem y otra VPC/región (peering/TGW).   Ambos endpoints son regionales; si el recurso está en otra región o necesitas on-prem/otra VPC → interface.
