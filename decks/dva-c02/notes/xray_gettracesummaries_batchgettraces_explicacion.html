X-Ray: GetTraceSummaries vs BatchGetTraces

La pregunta: ¿cuál es la diferencia entre GetTraceSummaries y BatchGetTraces?

Respuesta: C — GetTraceSummaries busca por rango de tiempo con una filter expression y devuelve IDs + annotations; BatchGetTraces recupera trazas completas por ID (sin filtro).

Son dos APIs que trabajan en pareja, en dos pasos: primero descubres qué trazas te interesan, luego traes el detalle. Entender ese flujo hace obvia la respuesta.

1. Repaso rápido: ¿qué es una traza?

Una traza (trace) es el recorrido completo de una petición a través de todos tus servicios. Cada traza tiene un TraceId y se compone de segments y subsegments (documentos JSON con el trabajo de cada salto).

Cuando depuras, tienes miles o millones de trazas. No puedes pedirlas todas. Necesitas: (1) filtrar las que importan, y (2) abrir solo esas para ver el detalle. Eso es exactamente lo que hace cada API.

2. El flujo de dos pasos (la clave)

sequenceDiagram participant App as Tu codigo / consola participant XR as X-Ray API Note over App,XR: PASO 1 - Descubrir App->>XR: GetTraceSummaries(StartTime, EndTime, FilterExpression) XR-->>App: TraceSummaries [ IDs + annotations + duracion + errores ] Note over App: Elijo los TraceIds que me interesan (hasta 5 por lote) Note over App,XR: PASO 2 - Detallar App->>XR: BatchGetTraces(TraceIds = [id1, id2, ...]) XR-->>App: Traces completas (todos los segments/subsegments)

Summaries = el buscador. BatchGetTraces = abrir el expediente completo de los que elegiste.

AnalogíaGetTraceSummaries es como buscar en Google: escribes un criterio (rango de fecha + filtro) y te devuelve una lista de resultados con títulos (los IDs y annotations). BatchGetTraces es hacer clic en unos cuantos resultados para leer la página completa.

3. GetTraceSummaries a detalle

Propósito: descubrir qué trazas existen en una ventana de tiempo que cumplan un criterio. Devuelve resumenes, no el detalle completo.

ParámetroObligatorioQué hace
StartTime / EndTimeSíLa ventana de tiempo (Unix seconds). Es la base de la búsqueda.
FilterExpressionNoCriterio adicional: por servicio, error, usuario, annotation, etc.
TimeRangeTypeNoInterpreta el rango por TraceId (inicio), Event (actualización) o Service (fin de segmento).
Sampling / SamplingStrategyNoTraer solo un subconjunto de resumenes.
NextTokenNoPaginación.

Devuelve TraceSummaries: cada uno trae Id, Annotations, Duration, EntryPoint, ErrorRootCauses, etc. Suficiente para decidir cuáles abrir, pero no los segment documents completos.

Ejemplos de filter expression

# Trazas que pasan por un servicio
service("api.example.com")

# Trazas con una annotation concreta
annotation.account = "12345"

# Trazas con error
error = true
# CLI: descubrir trazas con error en la ultima hora
aws xray get-trace-summaries \
  --start-time $(date -v-1H +%s) \
  --end-time $(date +%s) \
  --filter-expression 'error = true'

4. BatchGetTraces a detalle

Propósito: dado que ya sabes los TraceId, traer las trazas completas (todos los segments y subsegments). No filtra ni busca por tiempo.

ParámetroObligatorioDetalle
TraceIdsSíLista de IDs: de 1 a 5 por llamada.
NextTokenNoPaginación.

Devuelve Traces (cada una con sus Segments y sus Document JSON) y UnprocessedTraceIds (los que no se pudieron procesar). No acepta FilterExpression ni StartTime/EndTime.

Límite que cae en el examenBatchGetTraces acepta máximo 5 TraceIds por llamada. Si GetTraceSummaries te dio 50 IDs, haces 10 llamadas a BatchGetTraces (o paginas).
# CLI: traer el detalle de trazas concretas por ID
aws xray batch-get-traces \
  --trace-ids 1-5f84c7a1-e7d1... 1-5f84c7b2-a3f0...

6. Por qué NO las otras opciones

OpciónPor qué es falsa
A. Summaries configura sampling; BatchGetTraces filtra por annotationEl sampling se define con las Sampling Rules, no con Summaries. Y BatchGetTraces no filtra (ni por annotation ni por nada): solo trae por ID.
B. Ambas aceptan filter expressionsSolo GetTraceSummaries acepta FilterExpression. BatchGetTraces no.
D. BatchGetTraces acepta filter expressions; Summaries solo por IDInvertido. Es al revés: Summaries filtra por tiempo/expresión; BatchGetTraces va por ID.
C. Summaries filtra por tiempo + expresión (IDs+annotations); BatchGetTraces por IDCorrecta. Coincide con el contrato real de ambas APIs.

7. No confundir con sampling

Sampling ≠ estas APIsEl sampling decide qué porcentaje de peticiones se trazan (para no trazar el 100% y ahorrar). Se configura con Sampling Rules (reservoir + fixed rate), NO con GetTraceSummaries. El parámetro Sampling de Summaries solo dice "devuélveme un subconjunto de los resumenes", que es otra cosa.

8. Resumen para el examen (DVA-C02)

Puntos clave
  • Flujo de dos pasos: GetTraceSummaries (descubrir) → BatchGetTraces (detallar).
  • Buscar/filtrar → GetTraceSummaries (StartTime/EndTime + FilterExpression, devuelve IDs + annotations).
  • Traer detalle por ID → BatchGetTraces (1 a 5 IDs, sin filtro, devuelve trazas completas).
  • Solo Summaries acepta FilterExpression.
  • El sampling lo definen las Sampling Rules, no estas APIs.
  • Filter expressions típicas: service("..."), annotation.x = "...", error = true.
